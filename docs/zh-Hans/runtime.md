# 运行时设计

Core 的作业与执行范围统一管理流程，宿主适配负责外部操作及清理。

[架构总纲][architecture]

[architecture]: architecture.md

## Core 作业

Core 持有应用执行根、作业身份、启动方式、状态和结果，公开协程与作业契约独立于内核操作类型。
协程通过 Core 原语产生合法挂起点；子作业失败按 Core 的等待契约传播，不以内核默认连带失败代替。

## 执行根与上下文

宿主通过 `@bitagent/core/host` 的 `createExecutionRoot` 建立隔离的归属范围。
`run` 的同步入口、协程推进及宿主操作函数的同步调用使用当前执行上下文，调用退出时恢复先前上下文。
异步回调通过显式 `run` 重新进入仍开放的根；Promise 续体不继承归属。

根的 `close` 等待自有作业与资源收束，重复调用共享首次关闭的 Promise。
当前作业同步关闭所属根会被拒绝。
宿主操作须在自身结束之外安排根关闭，避免异步续体等待所属根、而根又等待该操作结束。

## 结束与清理

执行范围负责自有子作业收束，相应资源完成清理后才提交作业终态。
观察状态不隐式等待；执行终态与业务成败分开，套件根据返回值验收业务结果。

宿主适配连接取消通知、实际操作结束和清理完成，不把 Promise 桥接交给业务调用者。
停止等待或发出 abort 不代表外部操作已经结束。
`fromAsync` 以操作返回值或 Promise 的实际结束为收束依据；适配器须将资源释放纳入该完成边界。
取消通知可进入原生 `catch`，受理取消后的作业在收束后只提交 `cancelled` 或 `failed`。
通知后的处理和清理继续推进；通知前必须保护的清理由宿主显式声明 `cleanup: true`。

## 内核与控制机会

Effection 为每个执行根提供私有作用域和推进机制，Core 保留挂起值校验、取消注入、等待传播和终态裁决。
内核句柄及类型留在适配器内部。

宿主操作函数在首次让出执行权前仍是同步调用。
长计算和阻塞 I/O 须主动让出执行权或放到控制路径之外执行，Promise 包装本身不提供抢占。
