# 架构总纲

BitAgent 的模块按稳定职责分解，技能通过模块的公开契约组织业务。
应用实例持有这些机制的组合，控制台、脚本和其他交互端操作同一份应用状态。

## 模块职责

### 职责边界与源码组织

逻辑职责先于物理组织；目录和文件映射已经确定的边界，不以路径数量决定模块数量。

| 术语 | 含义 | 与源码组织的关系 |
| --- | --- | --- |
| 功能模块 | 按相关功能与职责组织公开能力的模块 | 目录映射其职责，不规定它是否包含其他模块，也不等于独立发布包 |
| 单元模块 | 围绕完整功能特性、不可拆为跨工程阶段部分交付的模块 | 可以由多个文件或组件实现，其结构位置由实际包含关系决定 |
| 父模块与子模块 | 模块之间存在包含关系时使用的称谓 | 不从功能分类、交付粒度或目录嵌套推定模块的包含关系 |
| 组件 | 在明确接口后封装的一组相关实现 | 可以由一个或多个源码文件实现，集中归属一个职责边界 |
| 源码文件 | 语言层面的代码组织单元 | 可以承载组件实现、类型声明或出口汇聚，不自动成为组件 |
| 公开契约 | 消费者可依赖的输入、效果、结果与生命周期约定 | 导出符号规定可见接口，但函数签名不是契约的全部 |
| 国际化与本地化 | 国际化机制支持多种语言，本地化资源提供具体语言的表达 | `I18n` 提供机制，界面和提示资源提供相应文本 |

功能模块说明职责分类，单元模块说明完整交付边界，父模块与子模块说明包含关系。
同一个模块可以符合多个维度，但这些维度不必一一对应。
下文按职责组织说明，以单元模块列出交付边界，不由展示分组强制确定父子层级。

[TypeScript 的模块][ts-modules]是语言层面的概念，带顶层导入或导出的文件具有自己的模块作用域。
这里的功能模块采用架构职责边界，不把每个 TS 文件当作一个功能模块。
[组件的接口与实现分组][components]也不同于文件、目录或发布包。
单组件单文件可以作为源码组织约定，但组件内部的文件拆分不改变它的责任归属。

模块入口汇聚公开能力，内部组件通过所属模块的边界协作。
跨模块消费者依赖公开契约，不依赖对方的私有文件布局。
类型、常量和辅助实现随其服务的职责归属，不因被复用就进入一个无责任边界的公共目录。

工程阶段按需要达成的能力切分需求，计划阶段按执行依赖安排任务。
它们与职责分解不是一一对应关系：一个工程阶段可以协作多个模块，一个模块也可以参与多个工程阶段。

### Compiler：TypeScript 前端

`Compiler` 把 TypeScript 输入转成可以在既有应用中执行的产物，并提供与当前定义对应的诊断和类型信息。
它负责语言与类型处理，通用执行和运行时值检查分别交给 `Runtime`。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Source` | 解析器、类型检查器、代码转换器 | 处理源码、导入解析、语法与类型诊断，产生执行产物 |
| `TypeContracts` | 契约编译器、描述提取器 | 从具体类型和函数签名生成运行时契约产物及模型声明所需元数据 |
| `Session` | 输入编译器、定义元数据提取器 | 使用 `Context/State` 的当前定义编译输入，向应用门面提供执行入口及对应的定义、类型元数据 |

编译时的不可表示类型由 `TypeContracts` 拒绝，实际值不符由运行时值契约拒绝。
输入中的无效名称由语言诊断报告，不以逐项业务执行代替检查。
交互编译使用应用的定义快照，不另建一份会与运行时名称查找分离的持久命名空间。
编译工作本身也采用保留控制受理机会的执行方式，长编译不独占运行中应用的观察与控制通路。

### Runtime：通用执行内核

`Runtime` 推进程序提供的流程，持有执行句柄、执行归属与清理状态。
它服务普通脚本、业务函数、模型生成和工具执行，不把通用执行解释成某种 LLM 活动。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Jobs` | 作业句柄、协程调度器、执行范围 | 承担启动、挂起、等待、取消及自有子作业的收束 |
| `ValueContracts` | 契约值工厂、值校验器 | 消费已编译契约产物，对实际参数和结果校验、形成相应数据副本 |
| `Functions` | 类型化业务函数包装器 | 用参数与结果契约包装普通业务流程，按业务声明的启动方式交付作业 |
| `Host` | 宿主异步适配器、清理适配器 | 将宿主操作接入协程执行和取消收束，不把 Promise 桥接负担交给业务调用者 |

编译产物是执行输入，不要求内核自行解析 TS 或选择模型。
作业机制报告执行终态，业务套件解释返回值是否满足业务目标。
观察已有状态与执行等待分开；资源所属机制完成清理后，内核才提交对应终态。

### Context：应用状态、事实与呈递

`Context` 管理应用定义及事实的可访问表示，提供从这些来源构建当前活动上下文的能力。
原始机制拥有自己的状态和记录，`Context` 组织其引用、快照与来源关系，不另造一份业务真相。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `State` | 定义登记簿、类型视图、对象关联表 | 持有当前定义、类型和对象关联，为编译、查找、观察及名称移除提供同一份应用状态 |
| `Facts` | 事实索引、来源记录器 | 收纳机制提交的事实与业务已核验结论，保留对象、版本、来源及已知结果 |
| `Presentation` | 选材接口、确定性投影器 | 按调用程序给出的范围与规则选择、归纳材料，保留必要依据、失败与未定效果 |
| `Prompt` | 提示资源绑定器、消息组装器 | 使用所选指令、材料和事实，通过 `I18n` 解析提示资源，组织消息角色、顺序和稳定的呈递布局 |

技能决定当前活动需要哪些材料及怎样解释业务事实；`Presentation` 提供执行这些选择和投影的机制。
类型化事件可以自动归并和计数，任意文本不能自动升级为已核验事实。
新活动可以不呈递历史，投影不删除来源，也不把缺少记录、失败或未知效果计为完成。

`Context/Prompt` 是构造提示的职责，不是另一个 LLM 实体或发送器。
它产出发送契约可以接受的提示与消息数据，不发起请求、不替技能选择工具，也不接管业务重试。
本地化从本次系统指令及其配套提示资源保持一致；原始助手消息、工具身份和续接凭证不因提示重组而被翻译或改写。
缓存布局只调整已选材料的呈递，不以保留旧历史或权限代替选材。

### Provider：模型连接与协议边界

`Provider` 发布与底层实现无关的连接、模型配置和协议适配契约。
`pi-ai` 或其他请求核心的类型、凭据处理和错误形状留在这个边界之后。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Models` | 提供商配置对象、模型规格登记器 | 固定连接配置及模型身份、能力和参数约束，处理明确选择而非隐式换模 |
| `Connections` | 连接工厂、协议预检器 | 检查配置和请求可表示性，管理显式凭据引用与连接范围内的续接状态 |
| `Protocols` | 请求编码器、流解码器 | 消费统一请求，映射消息、工具声明与缓存意图，输出有序响应数据、结束原因及归一化用量 |
| `Presets` | 官方连接预设 | 用同一协议机制提供配置约定；LLMock 替换远端服务，不替换基设控制链 |

提供商配置与实际请求分开，协议执行不承担业务重试、答案采纳或工具处理函数的执行。
未知或不可表示的请求能力在相应预检边界失败，不能静默降级为另一份请求。
协议续接数据由其连接机制保管，不能变成隐式的实体对话记忆。

### Generator：实体、生成与现场工具

`Generator` 把选定模型变成可调用实体，采用本次请求，并将模型输出交付为可观察的生成作业。
它管理模型调用和工具调用身份，业务流程仍由调用程序掌握。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Entities` | 实体工厂、命名实体访问器、工具视图 | 使用应用登记与模型配置取得实体，管理其生成生命周期，按本阶段绑定工具集合 |
| `Generations` | 请求采用器、响应累积器、同步裁决器 | 固定输入、调用提供商，提交流快照和结果，并在受控停止后收束传输 |
| `Tools` | 工具构造器、调用派发器、回执机制 | 结合已编译契约构造语义工具，把获准调用关联到原工具实例，派发一次实际执行并交付可验证来源的回执 |

`send` 消费调用者已构造的提示，不自动调用 `Context/Prompt`、积累历史或追加下一轮请求。
工具声明交给模型，处理函数及其资源保留在程序端；对象范围和实际权限由业务执行边界检查。
观察、生成裁决和工具派发分开，收到工具调用不等于执行它，更不等于业务完成。

### I18n：统一国际化契约

`I18n` 通过统一契约解析本地化资源，供界面文案和提示构造共同使用。
消费者提供所需语言、资源标识和消息参数，不依赖具体资源引擎的 API。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Resources` | 语言资源目录、资源解析适配器 | 组织本地化消息及其声明，将资源格式和具体引擎隔离在模块内部 |
| `Messages` | 消息解析器、参数检查器 | 根据指定语言与资源标识形成文本，报告资源或参数问题，不把错误诊断当作有效消息内容 |

`Interface` 与 `Context/Prompt` 分别决定自己需要的语言和资源，界面语言不自动成为业务输出语言。
本地化处理文案，不改变工具名、参数字段、对象身份或业务数据的含义。
提示模板和反馈文案由业务套件提供资源，国际化机制不代替业务提示策略。

### Interface：统一应用交互门面

`Interface` 接收外部交互并协调责任模块，将结果、诊断和可操作对象交还调用者。
它的应用门面是各交互端共同使用的契约，控制台不是唯一的应用控制器。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Application` | 应用组装入口、交互协调器 | 组装应用状态与执行范围，将编译入口交给 `Runtime`，把实际定义及对应类型元数据交给 `Context/State`，并委派查询观察及对象控制 |
| `Console` | TS 输入适配器、控制台会话 | 将控制台输入交给应用门面，接收诊断、定义回显与结果，挂载门面提供的 `bit` 能力和默认函数绑定 |
| `Rendering` | 结果呈现器、诊断呈现器 | 根据交互端需求呈现结构化结果与对象视图，通过 `I18n` 解析文案，不重新解释执行状态或业务成败 |

`Console` 通过应用门面使用编译能力，不直接操作 `Compiler` 的内部状态。
TUI、GUI 或其他交互端扩展同一门面，沿用应用状态、对象控制和反馈关系。
用户函数绑定、定义关联、作业状态与实体关闭仍分别由相应机制持有，渲染不会产生这些效果。

已声明操作委派给其责任模块，未知交互操作在入口拒绝。
源码错误交由 `Compiler` 诊断，实际值错误交由相应值契约报告；空值与未提供的区别保留到目标契约，不以默认动作掩盖。
对象丢弃由应用门面协调定义移除与所属机制的生命周期处理，不用名称消失代替资源释放。
观察和控制读取已提交状态，完成必要检查后受理，不排队等待长编译或业务结束。

### 技能与业务套件

官方与用户套件都在核心模块之外组合业务流程，使用相同的公开能力。
它们持有需求、提示资源、选材规则、现场工具、反馈策略和业务验收，向调用者交付可直接操作的作业。

类型化答案接收是套件组合，不是 `Generator` 内建的全能循环。
模型可以提出分组、译文和复核判断，套件核验后采纳，决定部分重试或写入实际产物。
新增业务通过套件扩展，不要求实体、协议适配器或界面增加业务专用分支。

### 模块协作与出口

下表规定直接协作的能力边界；数据产物的传递不把上层流程决策权交给下层。

| 消费者 | 依赖的公开能力 | 边界 |
| --- | --- | --- |
| `Runtime` | 宿主提供的操作与已编译契约产物 | 推进流程和检查值，不依赖 TS 编译器或模型实现 |
| `I18n` | 资源适配、`Runtime/ValueContracts` | 不依赖界面或提示构造器，消费者通过其契约取得文本 |
| `Context` | `Runtime/ValueContracts`；`Prompt` 使用 `I18n` | 持有状态、来源与呈递能力，不发送模型请求 |
| `Provider` | 显式宿主能力、`Runtime/ValueContracts` | 处理协议，不读取界面、技能或工具执行体 |
| `Compiler` | `Context/State`、`Runtime` | 使用当前定义生成执行输入，状态与执行机制不反向依赖语言实现 |
| `Generator` | `Context/State`、`Provider`、`Runtime` | 通过连接契约进行生成，不依赖提供商内部库或提示构造策略 |
| `Interface` | `Compiler`、`Context`、`Runtime`、`Generator`、`I18n` | 门面委派具体操作，交互适配器和呈现器不取得机制的私有控制权 |
| 技能与业务套件 | 本业务需要的模块公开契约 | 组织业务政策，不能从消息历史继承工具权限或将模型自述变成完成事实 |

功能模块的出口聚合其公开契约，组件实现保持在所属边界内。
库的导出路径可以汇聚多个功能模块；`@bitagent/core` 及其 `skills`、`providers`、`host` 入口不要求与功能模块目录一一对应。
模块分解不自行改名既有公共符号，也不把每个单元模块变成独立发布包。
