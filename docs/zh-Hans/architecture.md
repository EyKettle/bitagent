# 架构总纲

BitAgent 在持续运行的应用实例中执行 TypeScript 流程。
核心模块提供编译、执行、模型调用和交互能力，业务套件通过公开契约组合这些能力。

## 模块职责

### Compiler：TypeScript 前端

将源码转为执行产物，提供与当前应用定义一致的诊断和类型信息。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Source` | 解析器、类型检查器、代码转换器 | 解析源码和导入，检查语法与类型，产生执行产物 |
| `TypeContracts` | 契约编译器、描述提取器 | 从具体类型与函数签名生成运行时契约及模型声明元数据 |
| `Session` | 输入编译器、定义元数据提取器 | 使用 `Context/State` 的定义快照编译输入，向应用门面交付执行入口及定义、类型元数据 |

语言诊断在执行前完成，实际值检查由 `Runtime` 承担。
编译与名称查找使用同一份应用定义，长编译保留观察和控制的受理机会。

### Runtime：通用执行内核

以 [Effection][effection] 为私有内核推进原生 Generator 流程，对外提供 Core 的作业与执行范围。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Jobs` | 作业句柄、内核适配器、执行范围 | 管理启动、挂起、等待、取消及自有子作业收束 |
| `ValueContracts` | 契约值工厂、值校验器 | 校验实际参数与结果，形成相应数据副本 |
| `Functions` | 类型化业务函数包装器 | 以参数与结果契约包装业务流程，按声明的启动方式交付作业 |
| `Host` | 宿主异步适配器、清理适配器 | 将宿主操作及清理接入协程执行与取消收束 |

### Context：应用状态、事实与呈递

组织应用定义、事实来源及当前活动的上下文。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `State` | 定义登记簿、类型视图、对象关联表 | 持有当前定义、类型和对象关联，供编译、查找、观察及名称移除使用 |
| `Facts` | 事实索引、来源记录器 | 收纳机制事实与已核验业务结论，保留对象、版本、来源和已知结果 |
| `Presentation` | 选材接口、确定性投影器 | 按调用程序给定的范围和规则选择、归纳材料，保留依据、失败及未定效果 |
| `Prompt` | 提示资源绑定器、消息组装器 | 通过 `I18n` 解析提示资源，组装消息角色、顺序和稳定呈递布局 |

原始状态由相应机制持有，投影保留来源；新活动可以不呈递历史。
提示构造只产出请求数据，保留原始消息、调用身份与续接凭证；缓存布局只调整已选材料的呈递。
系统指令与配套提示资源保持本地化一致。

### Provider：模型连接与协议边界

以统一契约隔离模型配置、连接与底层请求实现。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Models` | 提供商配置对象、模型规格登记器 | 固定连接配置、模型身份、能力和参数约束 |
| `Connections` | 连接工厂、协议预检器 | 检查配置与请求可表示性，管理显式凭据引用和连接范围内的续接状态 |
| `Protocols` | 请求编码器、流解码器 | 映射消息、工具声明和缓存意图，输出有序响应、结束原因及归一化用量 |
| `Presets` | 官方连接预设 | 通过同一协议路径提供配置约定，包括 LLMock 预设 |

预检拒绝未知或不可表示的请求能力；续接状态归连接机制，不形成隐式实体记忆。
协议执行与业务重试、答案采纳、工具处理分离。

### Generator：实体、生成与现场工具

采用本次请求，管理模型调用及工具调用身份，交付可观察的生成作业。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Entities` | 实体工厂、命名实体访问器、工具视图 | 按应用登记和模型配置取得实体，管理生命周期并绑定本次工具集合 |
| `Generations` | 请求采用器、响应累积器、同步裁决器 | 固定输入、调用提供商，提交响应快照和结果，受控停止后收束传输 |
| `Tools` | 工具构造器、调用派发器、回执机制 | 根据编译契约构造语义工具，关联获准调用与原实例，派发一次实际执行并交付有来源的回执 |

`send` 只执行调用者构造的请求；观察、生成裁决与工具派发彼此分离。
工具处理函数及资源留在程序端，实际权限由业务执行边界检查。

### I18n：统一国际化契约

解析本地化资源，供界面呈现和提示构造使用。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Resources` | 语言资源目录、资源解析适配器 | 组织资源及其声明，隔离资源格式和具体引擎 |
| `Messages` | 消息解析器、参数检查器 | 按指定语言与资源标识形成文本，报告资源或参数问题 |

消费者各自选择语言和资源；本地化保留工具名、参数字段、对象身份与业务数据的含义。

### Interface：统一应用交互门面

接收外部交互，协调核心模块，返回结果、诊断与可操作对象。

| 单元模块 | 组件 | 职责 |
| --- | --- | --- |
| `Application` | 应用组装入口、交互协调器 | 组装状态与执行范围，委派执行、观察和对象控制，将实际定义及类型元数据发布到 `Context/State` |
| `Console` | TS 输入适配器、控制台会话 | 经应用门面提交输入、接收诊断与回显，挂载 `bit` 及默认函数绑定 |
| `Rendering` | 结果呈现器、诊断呈现器 | 呈现结构化结果、诊断和对象视图，通过 `I18n` 解析文案 |

交互端使用同一门面与应用状态。
源码错误交给 `Compiler`，实际值错误交给值契约；未知操作在入口拒绝，空值与未提供分别按目标契约处理。
对象丢弃协调名称移除与所属机制的清理；观察和控制完成必要检查后受理，不等待长编译或业务结束。

## 技能与业务套件

官方与用户套件在核心模块之外，通过相同公开能力组织业务。
套件持有需求、提示资源、选材规则、现场工具、反馈策略与验收，并交付可操作作业。
工具权限由当前执行边界决定；模型自述和消息历史不构成业务完成或授权。

## 直接协作

| 消费者 | 依赖的公开能力 |
| --- | --- |
| `Runtime` | 宿主操作、已编译契约产物 |
| `I18n` | 资源适配、`Runtime/ValueContracts` |
| `Context` | `Runtime/ValueContracts`；`Prompt` 使用 `I18n` |
| `Provider` | 显式宿主能力、`Runtime/ValueContracts` |
| `Compiler` | `Context/State`、`Runtime` |
| `Generator` | `Context/State`、`Provider`、`Runtime` |
| `Interface` | `Compiler`、`Context`、`Runtime`、`Generator`、`I18n` |
| 技能与业务套件 | 本业务需要的模块公开契约 |
